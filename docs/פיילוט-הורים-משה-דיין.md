מסמך הרצה. נכתב 06.10.2026.

המטרה: הורי התינוקייה עוברים ללוח החדש, והלוח הישן נסגר.

## כיתת הפיילוט

**תינוקיה 20 — 20 ילדים, 38 הורים.** 4 מהם כבר הפעילו חשבון, 34 יכולים
להפעיל עכשיו, אף אחד לא חסום.

זו גם הכיתה היחידה בסניף שיש לה לוח יומי בכלל. במשה דיין 75 ילדים פעילים
ב-3 כיתות, אבל פעוטות (25) ובוגרים (30) לא מקבלים לוח — זו הגדרת המערכת,
במכוון, והלוח הישן גם הוא היה רק לתינוקייה. כלומר אין מה "לפרוש" אליהם:
פיילוט הלוח הוא 20 משפחות, וזו המציאות ולא מגבלה של הפיילוט.

שאר 55 המשפחות כן יכולות להיכנס לפורטל כבר היום ולקבל ממנו הודעות, תמונות,
תשלומים, היעדרויות, מורשי איסוף וגאנט — פשוט בלי לוח יומי. זו החלטה נפרדת
שאפשר לקבל אחרי שהתינוקייה עובדת.

## מה שחשוב להבין לפני שמתחילים

**אין מתג "להפעיל פורטל לסניף".** הפורטל חי כבר עכשיו. כל הורה של ילד פעיל
במשה דיין יכול להיכנס אליו הערב, בלי שתעשה שום דבר. לכן הפיילוט הוא לא העלאה
לאוויר — הוא שלושה דברים אחרים:

1. לוודא שהנתונים מאפשרים לכל הורה להיכנס (ת.ז ונייד תקין על כל משפחה).
2. להביא את ההורים בפועל להפעיל חשבון.
3. לסגור את הלוח הישן — וזו החלטה, לא העברה.

**הלוח הישן** הוא דף ב-GitHub Pages שעוטף סקריפט של Google, מגובה בגוגל־שיט
אחד לכל סניף. הורים קוראים אותו ומזינים בו את "הבוקר בבית", וצוות ממלא בו את
היום. יש כבר סינכרון דו־כיווני בין שני הלוחות, שנבנה בדיוק כדי שסגירת הישן
תהיה החלטה ולא מיגרציה. התיעוד:

```
docs/superpowers/specs/2026-09-17-nursery-sheet-sync-design.md
docs/superpowers/plans/2026-09-17-nursery-sheet-sync.md
```

**הורים לא מקבלים התראות.** פרסום הודעה לא שולח כלום — ההורה רואה אותה בפעם
הבאה שהוא פותח את האפליקציה. הדבר היחיד שדוחף התראה להורה הוא תקציר התמונות
היומי, והוא עובד רק למי שהתקין את האפליקציה מהחנות. בדפדפן אין התראות להורים
בכלל. זו ההחלטה הגדולה שצריך לקבל בשלב 6.

## שלב 1 — לראות מי יכול בכלל להיכנס

הסקריפט קורא בלבד. לא כותב כלום, בשום מצב.


בלי `--classroom` זה מראה את כל הסניף.

מה אתה מקבל:

- לוח יומי לפי כיתה — איזו כיתה מקבלת לוח מלא, מקוצר, או כלום. **תינוקייה**
  מקבלת לוח מלא. **בוגרים** ו**צעירים** לא מקבלים לוח בכלל, במכוון. פיילוט על
  הלוח היומי לא אומר כלום לכיתה שאין לה לוח.
- כמה הורים יש, כמה כבר הפעילו חשבון, כמה יכולים להפעיל עכשיו.
- **בלי נייד תקין** — אלה חוסמים. הם לא יוכלו להיכנס עד שהמשרד יעדכן את
  המספר. ההורה רואה "לא רשום אצלנו מספר טלפון נייד עבורך".
- **ילדים בלי ת.ז הורה** — אותו דבר, חוסם.
- **בלי תאריכי התחלה/סיום ברישום** — לא חוסם כניסה, אבל באוגוסט–ספטמבר
  הפורטל עלול להציג את כיתת השנה הבאה כאילו היא ההווה, ואז הלוח היומי נעלם
  מהמסך של ההורה.

### ואז הדבר החשוב ביותר בכל המסמך


**אל תקרא את הרשימה הזו בטרמינל.** שורה שמערבבת שם בעברית עם ספרות לטיניות
מתהפכת על המסך: הת.ז והנייד נדבקים זה לזה ונראים כמו מספר אחד בן תשע־עשרה
ספרות. הנתונים תקינים — התצוגה לא. בקובץ הכל נשאר בעמודות.

**שב וקרא את השורות האלה אחת־אחת.**

מספר שחסר — המערכת תופסת ואומרת להורה לפנות לגן. מספר **תקין אבל שגוי** —
המערכת לא תופסת כלום. ההורה רואה מסך הצלחה, הקוד נשלח, והוא פשוט לא מגיע.
במקרה הרע הקוד מגיע לאדם זר. אין שום בדיקה אוטומטית שתופסת את זה. רק עין
אנושית שמכירה את המשפחות.

תקן מה שצריך במשרד לפני שממשיכים. **אחרי שעברת על הקובץ — מחק אותו.** הוא
מכיל תעודות זהות ומספרי טלפון של משפחות ואין לו מה לשבת על שולחן העבודה.

## שלב 2 — להכין את התפריט

"פתיתים" כבר נוסף לקוד בקטגוריית **פחמימה של ארוחת צהריים**. אבל התפריט החי
הוא לא הקוד — הוא רשומה במסד, והיא מתעלמת ממה שכתוב בקוד (זה במכוון: אסור
שמנה שמישהו הוריד תחזור מעצמה).

הדרך הקצרה: היכנס ללוח היומי באפליקציה, גלגל השיניים למעלה → הגדרות →
פחמימה → הוסף "פתיתים" → שמור. **הערה: התפריט משותף לכל הסניפים.**

הדרך דרך הסקריפט, אם אתה מעדיף לראות לפני:

```bash
cd "/Users/amitkohta/Desktop/Claude Code Apps/אפליקציות/gan-halomot/server" && node scripts/nursery-menu-add-dish.js --meal lunch --category פחמימה --dish פתיתים
```

זו הרצה יבשה — מדפיסה את הקטגוריה לפני ואחרי, ולא כותבת כלום. להוספה בפועל:

```bash
cd "/Users/amitkohta/Desktop/Claude Code Apps/אפליקציות/gan-halomot/server" && node scripts/nursery-menu-add-dish.js --meal lunch --category פחמימה --dish פתיתים --apply
```

אין צורך בדיפלוי. הלוח קורא את ההגדרה בכל טעינה.

אם ביקשו "פתיתים" בארוחת בוקר ולא בצהריים — אותה פקודה עם `--meal breakfast`.
להרצה בלי פרמטרים כדי לראות את כל התפריט שבאוויר:

```bash
cd "/Users/amitkohta/Desktop/Claude Code Apps/אפליקציות/gan-halomot/server" && node scripts/nursery-menu-add-dish.js
```

## שלב 4 — להביא את ההורים להפעיל חשבון

**אין מנגנון הזמנה בכמות.** אין כפתור "שלח לכולם". מה שיש:

הודעה לסניף דרך מסך ההודעות — `classroom_ids` ריק פירושו כל הסניף. לפני
שליחה, בדוק קהל:

```
GET /api/announcements/:id/audience
```

זה מראה כמה משפחות, כמה **לא ניתנות להשגה**, ומה העלות מול התקציב. מספר
"לא ניתנות להשגה" הוא בדיוק מספר המשפחות שלא יוכלו להצטרף לפיילוט.

שתי דרכים להוציא את ההודעה:

- **וואטסאפ** — המסך נותן לך טקסט מוכן להעתקה. אתה מדביק בקבוצה. לא עולה כלום.
  זו הדרך המומלצת להזמנה.
- **SMS דחוף** — עולה כסף אמיתי, עובד רק על הודעה שסומנה דחופה, ו**רק הכותרת
  נשלחת, לא הגוף**. הזמנה עם קישור צריכה להיכנס לכותרת.

### שתי מגרות שיפילו את הפיילוט אם לא תיזהר

**התקציב משותף עם קודי הכניסה.** אותה יתרה מראש־שולם ששולחת SMS להורים היא
זו ששולחת לכל הורה את קוד ההתחברות שלו. בליץ' SMS לכל הסניף פלוס ~54 קודי
הפעלה — הכול מאותו כיס. אם נגמר באמצע, אף אחד לא יכול להתחבר.

**אל תעשה "ערב הורים להפעלת האפליקציה".** יש תקרה של 10 אימותי קוד ל-15 דקות
**לפי כתובת IP**. חדר שלם על אותו וויי־פיי בגן הוא IP אחד — אחרי עשרה הורים
השאר נחסמים ומקבלים "יותר מדי ניסיונות". או שמפזרים בגלים לאורך ימים, או
שמבקשים מההורים להפעיל מהסלולר שלהם ולא מהוויי־פיי של הגן.

**אחרי שמפעילים — הרץ שוב את שלב 1** כדי לראות כמה עברו באמת.

## שלב 5 — לסגור את הלוח הישן

**לא לפני שעברת את שלב 1 במלואו ורוב ההורים הפעילו.**

הצ'ק־ליסט נכתב מראש בדיוק לפיילוט הזה, ומשה דיין נקוב בו כסניף הראשון:
`docs/superpowers/plans/2026-09-17-nursery-sheet-sync.md`, שורות 1941–1952.

ששת הצעדים:

1. התאמת ילדים יבשה למשה דיין — `scripts/sheet-sync-match.js`. **קרא את
   הרשימה שהוא מדפיס** ואז הרץ שוב עם `--write`.
2. הגדר את הסינכרון קריאה־בלבד למשה דיין:
   ```bash
   cd "/Users/amitkohta/Desktop/Claude Code Apps/אפליקציות/gan-halomot/server" && node scripts/sheet-sync-enable.js --mode read --only "כפר סבא - משה דיין" --write
   ```
3. **צפה ביום עבודה שלם.** הלוג אומר מה הוא היה כותב; שום דבר לא משתנה באף
   אחד משני הלוחות.
4. קרא את ההשוואה הלילית. **אפס אי־הסכמות הוא התנאי להמשך.** אי־הסכמה אחת
   עוצרת את הפיילוט עד שמבינים אותה.
5. הפוך לכתיבה:
   ```bash
   cd "/Users/amitkohta/Desktop/Claude Code Apps/אפליקציות/gan-halomot/server" && node scripts/sheet-sync-enable.js --mode both --only "כפר סבא - משה דיין" --write
   ```
   צפה ביום שני, כולל מספר הקונפליקטים.
6. רק עכשיו אפשר לסגור את דף הסקריפט הישן להורים.

לעצור את הסינכרון לגמרי כשכבר לא צריך אותו:

```bash
cd "/Users/amitkohta/Desktop/Claude Code Apps/אפליקציות/gan-halomot/server" && node scripts/sheet-sync-enable.js --mode off --only "כפר סבא - משה דיין" --write
```

הסקריפט קורא את ההגדרה בכל סבב — **אין צורך בדיפלוי** לאף אחת מהפקודות האלה.

### שני דברים שלא לשכוח

**הגוגל־שיטים נשארים כארכיון.** `scripts/import-nursery-history.js` הוא הדרך
לקרוא אותם אחר כך.

**יש גוגל־שיט באותה תיקיית דרייב בשם "חשבונות מייל - מחשבי לוח עדכון דיגיטלי"
שמחזיק ארבע כתובות ג'ימייל ואת הסיסמאות שלהן בטקסט גלוי.** אם הלוח הישן
נסגר, הסיסמאות האלה צריכות להתחלף או להימחק כחלק מהסגירה. זה נרשם בתיעוד
העיצוב של הסינכרון ועדיין לא טופל.

**מחיקת הקוד של הסינכרון היא משימה נפרדת ומאוחרת.** יש בה מלכודת: הסקריפט
נדרש ב-`src/index.js` בלי try/catch בתוך הקולבק של `app.listen`. מחיקת
התיקייה בלי להסיר את הקריאה מפילה את העלייה ו**משתיקה בשקט כל ג'וב שנרשם
אחריה, כולל לופ שליחת ההתראות**. הסדר המחייב רשום בתיעוד העיצוב, סעיף מחיקה.

## שלב 6 — ההחלטה על ההתראות

זו החלטה שצריך לקבל עכשיו ולא בדיעבד.

הורה שנכנס מהדפדפן מקבל את הלוח, את ההודעות ואת התמונות — **ובלי שום התראה**.
הוא יראה הודעה דחופה רק אם יפתח את האפליקציה מעצמו. פרסום הודעה לא דוחף כלום
לאף אחד.

שלוש אפשרויות:

1. **לדחוף התקנה של האפליקציה מהחנות** להורי משה דיין. אז הם מקבלים את תקציר
   התמונות היומי (18:00, או שישי 13:00 למי שבחר שבועי). עדיין: **הודעות לא
   דוחפות התראה גם באפליקציה.**
2. **להתייחס לפורטל כמשיכה בלבד** — ההורה פותח כשהוא רוצה — ולהשאיר נדנוד
   בוואטסאפ בשבועות הראשונים. הדרך הזולה והבטוחה לפיילוט.
3. **לפתח התראות דפדפן להורים.** זה פיתוח אמיתי, לא הגדרה: מודל המנויים
   דורש היום מזהה עובד, צריך מסלול רישום בטוקן הורה, ושירות ההתראות צריך ענף
   להורים. לא לפיילוט הזה.

ההמלצה: אפשרות 2 לפיילוט, ואז להחליט על בסיס מה שבאמת קרה.
