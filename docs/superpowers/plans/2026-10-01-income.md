# Income (Finance Part 3) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A "הכנסות" screen: קפלן parent transfers matched to families and months (without touching collections), ClickTac monthly debt reports imported per branch, and Emunah's monthly settlement imported, reconciled to the bank and cross-checked with ClickTac.

**Architecture:** New models + services; reads collections/households/bank, writes only its own collections; one REST router behind `income` / `income_write`; one React screen with 3 tabs.

**Tech Stack:** Node/Express, Mongoose, `xlsx`, React + MUI, mongodb-memory-server.

**Spec:** `docs/superpowers/specs/2026-10-01-income-design.md`

## Global Constraints

- NEVER write `Collection` / `Registration` / `ExternalEnrollment` from this module (spec "הכרעה מרכזית"). The only touch on collections is an additive read-only field on `GET /collections` rows (Task 6).
- Bank pool: `BankTransaction.amount > 0`, `type:'bank'` accounts, not `is_internal_transfer`, date ≥ `expenseCore.getStartDate()`, not matched by an active `IncomeRule` (contains, case-insensitive). Built-in income rules (seeded at boot, idempotent, never in a GET): "אמונה" (label "העברה מאמונה — בלשונית אמונה"), "ריבית", "החזר", "זיכוי".
- קפלן branch = `Branch` whose name matches /קפלן/ (same as sync.controller). Households via `services/household.service.buildHouseholds`; expected monthly amounts via the same derivation the collections screen uses (`services/collection-view.service`).
- Kaplan scoring (ruling): name overlap ≥0.6 → +40, >0 → +15 (tokens ≥3 chars from both parents' names vs description + counterparty, reuse `expenseCore.vendorKey`-style normalisation); amount = household monthly expected ±2 ₪ → +45, = 2× or 3× → +30; transfer date within the billing month or the previous one → +15; payer alias hit → score 100. Propose when ≥55. Greedy global assignment like the expense engine.
- Allocation: Σ allocations of a transaction ≤ amount + 2 ₪; default split = earliest open months (expected > allocated) across the household's children in that academic year until the amount is used.
- ClickTac IDs: digits padded to 9; passports upper-cased as is.
- Emunah parse by label text, not cell positions; "X"/empty = null; numbers may be floats.
- Tab `income` defaultRoles `['system_admin','admin_viewer','accountant']`; grant `income_write` (`path:null`, `writeGrantFor:'income'`) defaultRoles `['system_admin','accountant']`, both tab files.
- Tests: memory Mongo, dotenv stubbed, synthetic xlsx (no real personal data in fixtures); NEVER load `server/.env`. UI: theme colours only (hex stays 602), Hebrew, apiError, phone cards.
