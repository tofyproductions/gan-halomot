# הוצאות — מסמכים ושיוך (חלק 2א של מערכת הכספים)

**נכתב:** 01.10.2026 · **סטטוס:** מאושר בעל-פה (הבעלים: "כן מאשר", 01.10) · **חלק 2א מתוך 3**

תלוי ב: חלק 1 (`2026-10-01-bank-feed-design.md`) — תנועות בנק וכרטיסים חיים מאז 01.10.
הפניה לאלגוריתמים: `2026-10-01-expenses-port-notes.md` — הנוסחאות המדויקות של טופי (ניקוד, שיוך,
כיסוי, קבלות, חוקים, חיפוש). **כשהמסמך הזה אומר "כמו בטופי" — ההערות האלה הן המקור, מספר-מספר.**
חלק 2ב (אייקאונט: קריאת קיים + העלאה) — מסמך נפרד.

## למה

כל שקל שיוצא מחשבון הגן או מכרטיסי Max צריך מסמך מאחוריו. היום אין במערכת של הגן שום מסמך הוצאה.
הבעלים רוצה את מה שעובד בטופי: חשבונית מוצעת לחיוב, מאשרים בלחיצה, וקבלות מחכות לחשבונית שלהן.

## החלטות בעלים (01.10.2026) — לא לפתוח מחדש

1. **סניף לכל הוצאה** — בדרך כלל סניף, לפעמים "כללי". החשבונית לא אומרת (הכל על שם "גן החלומות ע״ר"),
   לכן השיוך ידני; כשיש הזמנה מקושרת — מוצע ממנה.
2. **קישור להזמנה** — חשבונית מוצעת להזמנה של אותו ספק; סניף נלקח ממנה; אזהרה על פער סכום.
3. **הגן עמותה שלא מקזזת מע״מ** — כל הוצאה בסכום המלא כולל מע״מ. אין פיצול, אין "חלק מוכר".
4. **מדיניות קבלות כמו בטופי** — לאייקאונט רק חשבוניות; קבלה מחכה לחשבונית שלה; ספק פטור/עמותה
   מסומן פעם אחת לכל ספק ואז הקבלה שלו היא המסמך. חשבונית שלא הגיעה תוך 14 יום — "באיחור".
5. **מקורות:** מערכת מיון המיילים (שלוש התיבות) + העלאה ידנית. **בהעלאה ידנית — הקלדת שדות בלבד,
   בלי קריאה אוטומטית.**
6. **הרשאות:** עמית, בן, אורלי — משייכים. אלעד — צפייה. (העלאה לאייקאונט — 2ב.)

## מה נבנה

### 1. מסמך הוצאה

מודל `ExpenseDocument`:

| שדה | מה |
|---|---|
| `source` | `mail_sorter` / `manual` |
| `mail_sorter_id` | מזהה במערכת המיון (ייחודי כשקיים) — הקובץ נמשך ממנה לפי דרישה, לא נשמר אצלנו |
| `file_id` | להעלאה ידנית: קובץ ב-`ExpenseFile` (base64, עד 10MB) — מופרד כדי שרשימות לא ימשכו בתים |
| `attachment_sha256` | למניעת כפילות |
| `supplier_id` | `Supplier`, כשזוהה |
| `vendor_name`, `supplier_tax_id` | כפי שנקראו/הוקלדו |
| `doc_type` | `tax_invoice` / `invoice_receipt` / `receipt` / `credit_note` / `other` |
| `doc_number`, `doc_date` | |
| `amount_total` | כולל מע״מ — **זה הסכום, אין אחר** |
| `currency`, `amount_original`, `fx_confirmed` | מט״ח: כמו בטופי — שקלים נלקחים מהחיוב בבנק באישור הזוג |
| `branch_id` / `is_general` | סניף, או כללי. אפשר ריק עד שמשייכים |
| `order_id` | הזמנה מקושרת |
| `needs_review` | ממערכת המיון: `true` עד שאדם אישר את השדות |
| `linked_invoice_id` | לקבלה: החשבונית שהיא מאשרת |
| `receipt_disposition` (+`_at`) | כמו בטופי: `has_invoice` / `is_document` |
| `status` | `active` / `void` |
| `created_by`, `confirmed_by`, זמנים | |

**כפילות:** אותו `mail_sorter_id`, אותו `attachment_sha256`, או אותו ספק + מספר מסמך (ספק מנורמל
כמו `vendorKey` בטופי) — נחסם בהודעה ברורה, עם קישור למסמך הקיים.

### 2. ספקים

`Supplier` מקבל: `tax_id` (מספר עוסק — אייקאונט מזהה ספק לפיו, נדרש ב-2ב) ו-`receipt_is_document`
(עוסק פטור/עמותה). זיהוי ספק למסמך: לפי מספר עוסק, אחרת לפי שם מנורמל; לא נמצא — המסמך נשאר עם שם
הספק כטקסט וכפתור "הוסף ספק" שיוצר `Supplier` עם השם והמספר. **לא נוצר ספק בלי לחיצה.**

### 3. משיכה ממערכת המיון

- `listDocuments('invoice')` ו-`listDocuments('receipt')` לגן (`system=gan`), כל 6 שעות (job עם
  `withJobLock`, כמו השאר) + כפתור "משוך עכשיו".
- שדות שמערכת המיון כבר קראה (`extracted`): `vendor_name, supplier_tax_id, doc_number, doc_date,
  amount_total, doc_type, currency` → למסמך, `needs_review: true`.
- `ack(id)` רק אחרי שנשמר אצלנו. פריט שכבר קיים (לפי `mail_sorter_id`) — מדולג, לא נכתב שוב.
- **אין קריאה בתשלום מהצד שלנו.** מערכת המיון קראה; הגן רק מעתיק.
- לא מוגדר (`MAIL_SORTER_URL/TOKEN`) — הכפתור אומר זאת; אין נפילה.

### 4. העלאה ידנית

"+ מסמך": קובץ (PDF/תמונה, עד 10MB, צילום מהטלפון נתמך) + שדות: ספק, סוג, מספר, תאריך, סכום,
סניף/כללי, הזמנה (אופציונלי). נשמר `needs_review: false` — מי שהקליד אישר.

### 5. החיובים

ממה שחלק 1 הביא: `BankTransaction` עם `amount < 0` מחשבון הבנק ומהכרטיסים, **בלי**:
העברות פנימיות (כולל חיובי Max בבנק שקושרו לכרטיס), חיובים שכוסו במלואם, וחיובים שחוק "לא צריך
חשבונית" תופס (כמו בטופי — החוק לא סוגר מסמך, רק מוציא חיוב מהתור).

### 6. שיוך — כמו בטופי

- ניקוד `scorePair`, סף 55, התאמת זוגות גלובלית `pairQueue`, חלופות (5), ירוק/אדום לשדה — לפי
  הערות הפורט §1–§2, מספר-מספר. בלי מקדם ניכוי במקור (לא רלוונטי לגן; נשאר כבוי).
- אישור זוג — `ExpensePayment {document_id, transaction_id, amount}` בפעולה אחת; דחייה — נזכרת
  (`ExpensePairRejection`); "עוד לא שולמה — להעלות בכל זאת" (`ExpenseUnpaidMark`).
- **כיסוי:** מסמך סגור כשהתשלומים מכסים את הסכום בסבילות **2 ₪** (§4). "סגור בכל זאת" / "שולם מחוץ
  לבנק" — החלטות שמורות (`ExpenseDocDecision`), כמו בטופי.
- מסמך `needs_review` מופיע בתור עם שדות לעריכה בשורה ו"✓ נכון — אשר ושייך" (כמו בטופי).
- **המלכודת מטופי:** אישור מסמך לא מעלים אותו מהתור (טופי: החשבונית נעלמה והופיעה בלי שם תחת חיוב).
  המנוע מעוגן במסמך, לא בחיוב.

### 7. קבלות — כמו בטופי, בלי קריאה בתשלום

- לשונית קבלות: ממתינות לחשבונית, "באיחור" מ-14 יום, מקושרות לאחרונה.
- **קישור לחשבונית:** בטופי מספר החשבונית נקרא מהקבלה ע״י מודל. בגן אין קריאה כזו — לכן: מועמדים
  (אותו ספק, עד 120 יום, לפי §5.6) וקישור בלחיצה. **אין קישור אוטומטי** — ובמיוחד שום GET לא כותב
  (המלכודת של טופי: `GET /receipts` כתב).
- "הספק עוסק פטור / עמותה" — נשמר על הספק (`receipt_is_document`); הקבלות שלו מתנהגות כחשבוניות.
- העברת תשלום מקבלה לחשבונית שלה — כמו בטופי (§5.7).

### 8. חוקי "לא צריך חשבונית"

`NoInvoiceRule {label, pattern, built_in}` — תיאור החיוב מכיל את התבנית. 5 קבוצות מובנות (§6.2 של
הערות הפורט: משכורות, עמלות בנק, מס/מע״מ, ביטוח לאומי, החזרי הלוואות), לא ניתנות למחיקה; אפשר
להוסיף. החזרים להורים ותשלומים לאמונה **אינם** חוקים — הם הכנסות/חלק 3.

### 9. קישור להזמנה

- מועמדות: הזמנות של אותו ספק בסטטוס `sent` / `pending_receive` / `receiving` / `received` /
  `received_partial`, שתאריך הקבלה (או השליחה) שלהן בין 30 יום לפני תאריך המסמך ל-60 יום אחריו.
- סכום ההזמנה להשוואה: מה שהתקבל (`qty_received × unit_price`, כולל מע״מ לפי `vat_rate` של הספק)
  כשיש קבלה; אחרת `total_amount`.
- הצעה ראשונה: ההפרש הקטן ביותר. קישור בלחיצה; ממלא סניף אם ריק.
- **אזהרה** כשההפרש בין המסמך להזמנה מעל 2 ₪: "החשבונית גבוהה ב-X ₪ ממה שהתקבל".
- הזמנה מקושרת לכל היותר למסמך פעיל אחד מסוג חשבונית.

### 10. המסך — "הוצאות"

נתיב `/expenses`, בעיצוב הגן, מבנה כמו `ExpensesShell` בטופי (§8):

1. **🎯 לשייך** — זוגות מוצעים, שורה לכל זוג; קבוצות "מסמכים בלי הצעה", "חיובים בלי מסמך — איזו
   חשבונית זו?". סניף והזמנה נבחרים ישירות בשורה.
2. **🧾 קבלות**
3. **✅ סגור** — מסמכים סגורים + "עוד לא שולמה". עמודת אייקאונט מציגה "לא חובר" עד 2ב.
4. **🔎 חיפוש** — טקסט, מספר מסמך, מספר עוסק, טווח סכום (§7); מסמכים וחיובים.
5. **⚙️ כלים** — חוקים, משיכה ממערכת המיון ומצבה, ספקים בלי מספר עוסק.

פס עליון: "+ מסמך", מונים לכל לשונית (קריאה אחת, `/counts`), סינון סניף.
טלפון: כרטיסים. שגיאות בעברית (`apiError`); טעינה שנכשלה ≠ ריק.

### 11. הרשאות

- לשונית `expenses`, `defaultRoles: ['system_admin', 'admin_viewer', 'accountant']`.
- כתיבה: `expenses_write` (מודל `clicktac_write` / `bank_write`), `['system_admin', 'accountant']`.
- קבצים: אותן הרשאות קריאה.

## מה לא בחלק הזה

אייקאונט (2ב). הכנסות (3). קריאה אוטומטית בתשלום. זיכויים מול החזרים. מחיקה סופית של מסמך
(רק `void`).
