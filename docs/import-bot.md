# בוט הייבוא — מה הוא שולח ומה מותר לו

הבוט קיים מפני שלסיבוס ולקליקטאק אין API. את הדוחות אפשר להוציא רק מהאתרים
שלהם, מאחורי ההתחברות שלהם. לכן משהו נכנס לשם, מוריד, ושולח את הקובץ לכאן.

בסיבוס זה שווה יום שלם: האתר מחזיק את הדוח של החודש ב-1 ב-00:01, והמייל מגיע
ב-2. עד שהקובץ לא בפנים, חודש השכר לא נסגר.

---

## מה הבוט יכול לעשות — וזה הכל

| מה | כתובת |
|---|---|
| דוח סיבוס החודשי | `POST /api/import-bot/cibus` |
| דוח מקליקטאק, לסניף אחד | `POST /api/import-bot/clicktac` |
| בדיקת קובץ קליקטאק בלי לכתוב | `POST /api/import-bot/clicktac/validate` |

בסיס: `https://gan-halomot.onrender.com`

שלוש כתובות, כולן `POST`, כולן העלאה. **אין שם אף קריאה ולא תהיה.** הבוט לא
יכול לשאול כלום על ילד, על עובדת, על שכר או על תמונה — הוא מוסר קובץ ומקבל
ספירה בחזרה.

זה **לא חשבון**. אין שם משתמש, אין סיסמה, ואי אפשר להרחיב לו הרשאות ממסך
ההרשאות בטעות. זו אותה תבנית שבה ה-Pi-ים בסניפים עובדים כבר שנים.

## 1. הרשאה

מפתח משותף אחד, שלוש כותרות בכל בקשה:

| כותרת | מה בתוכה |
|---|---|
| `X-Import-Key` | הסוד עצמו, כפי שהוא ב-Render |
| `X-Import-Ts` | הזמן עכשיו בשניות (unix) |
| `X-Import-Sig` | HMAC-SHA256 על המחרוזת `<ts>.` עם הסוד כמפתח, ב-hex |

חותמת זמן מלפני יותר מ-5 דקות נדחית — כדי שבקשה שמישהו הקליט לא תרוץ שוב מחר.
שתי ההשוואות (מפתח וחתימה) בזמן קבוע, כדי שלא ידלוף מהן כמה מהסוד ידוע.

### איך יוצרים את הסוד

ב-Render, על שירות `gan-halomot` → Environment:

```bash
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
```

את התוצאה ל-`IMPORT_BOT_SECRET`. **בלי המשתנה הזה כל שלוש הכתובות מחזירות 503**
— תכונה שלא הוגדרה היא סגורה, לא פתוחה עם מפתח שאפשר לנחש. פחות מ-32 תווים
נחשב כלא מוגדר, כי כאן הסוד הוא כל האימות.

וגם, חובה לקליקטאק:

```
IMPORT_BOT_CLICKTAC_BRANCHES=69dde62467ff14714973a158,69dde62467ff14714973a15c,69df6a19dcde21f40a7a020b
```

זה משה דיין, תל אביב והרצליה. **קפלן לא ברשימה** — ראה למטה.

`IMPORT_BOT_RATE_MAX` (אופציונלי, ברירת מחדל 40) — תקרת העלאות בשעה.

### יצירת החתימה

```bash
TS=$(date +%s)
SIG=$(printf '%s.' "$TS" | openssl dgst -sha256 -hmac "$IMPORT_BOT_SECRET" -hex | sed 's/.* //')
```

## 2. מה חוזר לבוט

ספירות בלבד:

```json
{ "ok": true, "month": "2026-09", "matched": 34, "unmatched": 2 }
```

**אף שם לא יוצא.** לא שם של עובדת, לא שם של ילד, לא ת"ז, לא טלפון ולא סכום של
אדם מסוים. שני הייבואים מחזירים בפנים המון שמות — מי לא הותאם, מי נדחה, מי חסר
— והדלת מקצצת את זה לפני שזה יוצא. גם אם מי שמפעיל את הבוט שומר כל בקשה וכל
תשובה, אין שם מידע אישי.

השמות כן נשמרים אצלנו, במסכים שבהם רואים אותם. רק לא נשלחים החוצה.

## 3. סיבוס (Pluxee)

```bash
curl -X POST "$API/api/import-bot/cibus" \
  -H "X-Import-Key: $IMPORT_BOT_SECRET" \
  -H "X-Import-Ts: $TS" \
  -H "X-Import-Sig: $SIG" \
  -F "file=@cibus-09-2026.xlsx"
```

| | |
|---|---|
| שם שדה הקובץ | `file` |
| פורמטים | `xlsx`, `csv` |
| metadata חובה | **אין** |
| metadata אופציונלי | `month` (`YYYY-MM`), `force`, `dry_run` |
| האם מפרסר | **כן, לגמרי** — הקובץ לא נשמר |
| לאן נשמר | `PayrollMonth.manual.cibus` — סכום לכל עובדת, בחודש השכר שלה |

הקובץ **לא נשמר בשום מקום**. הוא מפורסר, הסכומים נכנסים לחודש השכר של כל
עובדת, והמקור נזרק. העמודות מזוהות לפי שמות ולא לפי מקום, כדי שסדר עמודות שהשתנה
לא ישבור את הייבוא.

התאמה לעובדת: לפי ת"ז, ואם אין — לפי שם, בדרישה לשתי מילים משותפות לפחות, כדי
ששם משפחה משותף לבדו לא יחייב את האדם הלא נכון.

### חודש

`month` הוא לא חובה, **ועדיף בלעדיו**: קובץ שהורד ב-1 בחודש הוא של החודש שעבר,
והמערכת גוזרת את זה לבד — באותו היסט שהעבודה המתוזמנת משתמשת בו, כדי ששתיהן
תסכמנה על אותו חודש.

אם כן שולחים: תבנית `YYYY-MM`, וחודש עתידי או יותר מ-3 אחורה נדחה. השמירה הזאת
קיימת בגלל שגיאת כתיב בשנה — `2025-09` במקום `2026-09` היה משכתב שכר שנסגר לפני
שנה, ואת החודש הזה אף אחד לא קורא שוב.

## 4. קליקטאק

```bash
curl -X POST "$API/api/import-bot/clicktac" \
  -H "X-Import-Key: $IMPORT_BOT_SECRET" \
  -H "X-Import-Ts: $TS" \
  -H "X-Import-Sig: $SIG" \
  -F "file=@children-moshe-dayan.xlsx" \
  -F "branch_id=69dde62467ff14714973a158"
```

| | |
|---|---|
| שם שדה הקובץ | `file` |
| פורמטים | `xlsx` (וכל מה ש-`xlsx` קורא) |
| metadata חובה | **`branch_id`** |
| metadata אופציונלי | `academic_year` (לקובץ של שנה קודמת) |
| האם מפרסר | **כן, לגמרי** — הקובץ לא נשמר |
| לאן נשמר | `ExternalEnrollment` — שורה לכל ילד/ה, במצב `pending` עד שמאשרים |

**סוג הדוח לא נשלח.** הכותרת של הקובץ מזוהה לבד, והתשובה אומרת מה זוהה
(`export_type`). כרגע מזוהים שני ייצואים: `registrations` (ייצוא הנרשמים — ההורים
ואמצעי התשלום) ו-`contracts` (ייצוא החוזים — הכיתה והדרגה). דוחות נוספים
מקליקטאק ידרשו הוספת זיהוי, אבל **לא** כתובת חדשה ולא הרשאה חדשה.

**שנת לימודים לא נשלחת.** היא נקראת מהעמודה `שנת לימודים` שבקובץ. אם הקובץ אומר
שנה אחת והבקשה אומרת אחרת, זה נדחה עם שתי השנים בשמן, לפני שנכתבה שורה.

### הסניף — הדבר היחיד שחייב להיות נכון

**`branch_id` חובה. הבוט לא מנחש אותו ואין ברירת מחדל.**

בשני סוגי הייצוא, העמודות `מוסד` ו-`מעון` כותבות את **העיר** — ושני סניפים
עונים ל"כפר סבא". הקובץ לא יכול להגיד לאיזה גן הוא שייך. לכן הסניף תמיד היה
פרמטר שנבחר ביד.

המיפוי:

| הדוח שהבוט מוריד | הסניף | `branch_id` |
|---|---|---|
| הרצליה | הרצליה הרצוג | `69df6a19dcde21f40a7a020b` |
| כפר סבא | כפר סבא - **משה דיין** | `69dde62467ff14714973a158` |
| תל אביב יפו – אייזיק חריף | תל אביב - יפו | `69dde62467ff14714973a15c` |
| — | כפר סבא - **קפלן** | **אף פעם לא** |

**קפלן הוא רישום עצמאי וגבייה שלנו.** לקליקטאק אין עליו כלום, ולכן העלאה
שמכוונת אליו היא בהכרח טעות הגדרה. זה נחסם ב-403 `BRANCH_NOT_FROM_CLICKTAC`,
לפי `IMPORT_BOT_CLICKTAC_BRANCHES`. הוא **חייב** להיות מוגדר: זה המקום היחיד
שההבדל בין קפלן למשה דיין יכול לחיות בו, כי העמודה בקובץ אומרת "כפר סבא" על
שניהם.

### שמירת עיר

לפני שנכתבת שורה, העיר שבקובץ מושווית לעיר של הסניף. קובץ של הרצליה שמכוון לתל
אביב נדחה ב-400 `CITY_MISMATCH` — זו הטעות שבוט באמת עושה, שורת הגדרה שהועתקה
ושדה אחד לא שונה.

היא **לא** תופסת את קפלן מול משה דיין, ולא תתפוס: שתיהן "כפר סבא". בשביל זה יש
את רשימת ההיתר.

## 5. העלאה חוזרת של אותו חודש / אותו סניף

**סיבוס — שגיאה, לא דריסה.** חודש שכבר יובא בהצלחה נדחה ב-409
`ALREADY_IMPORTED`. לא בגלל חשבון — הייבוא קובע את הסכום ולא מוסיף אליו, אז
חזרה היא לא נזק אריתמטי. אלא בגלל שבין שתי ההרצות הרו"ח עשויה לתקן מספר ביד,
וההרצה השנייה הייתה מוחקת את התיקון בשקט. **בוט שמקבל 409 צריך לעצור.**
`force=1` הוא העקיפה של המשרד, מאדם שיודע מה הוא מוחק.

**קליקטאק — מיזוג, לא דריסה ולא שגיאה ולא גרסאות.** כל שורה מותאמת למה שכבר
קיים (לפי ת"ז, ואם צריך לפי שם + תאריך לידה), והתשובה מפרידה `created` /
`updated` / `unchanged`. אותו קובץ פעמיים → כל השורות `unchanged`. קובץ מעודכן →
רק מה שהשתנה מקבל `updated`.

**כל העלאה מקבלת `import_id` משלה, וניתן לבטל אותה לבד:**

```
DELETE /api/external-enrollments/imports/<import_id>
```

הביטול מדויק ומסרב לגעת בשורות שכבר הפכו לרישום. הוא **לא** נגיש לבוט — הוא
במסך "רישום לאמונה", לאדם.

## 6. בדיקה יבשה

**סיבוס — `dry_run=1`.** מפרסר, מתאים, סופר, ולא כותב כלום: לא את חודש השכר, לא
את יומן סיבוס ולא את יומן הבוט.

```bash
curl -X POST "$API/api/import-bot/cibus" ... -F "file=@x.xlsx" -F "dry_run=1"
```

```json
{ "ok": true, "dry_run": true, "month": "2026-09", "matched": 34,
  "unmatched": 2, "detected_columns": ["name","id","amount"],
  "already_imported": false }
```

`detected_columns` הוא מה שצריך ביום שפלאקסי משנים את הייצוא.

**קליקטאק — כתובת נפרדת, `/clicktac/validate`.** מזהה איזה ייצוא זה, בודק את
העיר מול הסניף, סופר שורות, ולא כותב כלום.

```json
{ "ok": true, "dry_run": true, "export_type": "registrations",
  "rows": 77, "branch": "כפר סבא - משה דיין" }
```

זו כתובת נפרדת ולא דגל, בכוונה: לייבוא עצמו אין מצב יבש — הוא ממזג מול מה
שקיים, שורה שורה — ודגל שהיה מדלג על הכתיבה היה מימוש שני של המיזוג, וזה הדבר
היחיד שכל התכונה הזאת נכתבה כדי להימנע ממנו. לכן היא שאלה קטנה יותר, והיא כנה
לגבי זה: היא לא יכולה להגיד לאיזה משני הגנים של כפר סבא הקובץ שייך, כי שום דבר
לא יכול.

**אין staging.** ייבוא קליקטאק נכנס ישר, אבל לא הופך לרישום לבד: השורות במצב
`pending` עד שאדם מקדם אותן. זה השלב שבו טעות נעצרת.

## 7. קודי תשובה ומגבלות

**מגבלת גודל: 10MB לקובץ.** ייצוא של 77 שורות הוא 27KB, וחודש סיבוס קטן ממנו.

| קוד | מתי | מה הבוט צריך לעשות |
|---|---|---|
| 200 | נכנס | להמשיך |
| 400 `NO_FILE` | לא צורף קובץ | תקלה בבוט |
| 400 `NO_BRANCH` | קליקטאק בלי `branch_id` | תקלה בהגדרה |
| 400 `BAD_MONTH` | חודש לא תקין / עתידי / >3 אחורה | תקלה בהגדרה |
| 400 `CITY_MISMATCH` | הקובץ של עיר אחרת מהסניף | **מיפוי שגוי — לעצור** |
| 400 `WRONG_EXPORT_TYPE` | הקובץ אינו ייצוא מוכר | הייצוא בקליקטאק השתנה |
| 400 `YEAR_MISMATCH` | שנת הקובץ ≠ השנה שנשלחה | תקלה בהגדרה |
| 403 `BRANCH_NOT_FROM_CLICKTAC` | סניף שלא מקבל קליקטאק | **מיפוי שגוי — לעצור** |
| 404 `BRANCH_NOT_FOUND` | `branch_id` לא קיים | תקלה בהגדרה |
| 409 `ALREADY_IMPORTED` | החודש כבר בפנים (סיבוס) | **לעצור, לא לנסות שוב** |
| 422 `PARSE_FAILED` / `UNREADABLE` | הקובץ לא נקרא | הייצוא השתנה |
| 429 `RATE_LIMITED` | יותר מ-40 בשעה | להמתין שעה |
| 401 `UNAUTHORIZED` / `STALE` / `BAD_SIGNATURE` | מפתח, זמן או חתימה | תקלה בבוט |
| 503 `NOT_CONFIGURED` | הסוד לא מוגדר בשרת | להתריע, לא לנסות שוב |

כל שגיאה בתבנית `{"error": {"code": "...", "message": "..."}}`.

## מה קורה בכל העלאה, אצלנו

1. **הקובץ מיובא** דרך אותו קוד בדיוק שההעלאה הידנית מריצה. אין מימוש שני,
   בכוונה: זה מה שמבטיח שקובץ שהבוט שלח וקובץ שהועלה ביד ייצרו שורות זהות.
2. **הריצה נרשמת ביומן הבוט** — הצלחות וסירובים. סירוב הוא השורה החשובה שם: זה
   הבוט מספר לנו שהוא ניסה. יומן שקט פירושו בוט שהפסיק לעבוד.
3. **סיבוס נרשם גם ביומן סיבוס הקיים**, כ-`bot`. זה לא קוסמטי: העבודה
   המתוזמנת קוראת אותו כדי לדעת שהחודש כבר נכנס — בלי זה היא הייתה מייבאת שוב
   מהמייל ב-2 בחודש — והתראת השקט קוראת אותו כדי לדעת שכלום לא הגיע.
4. **מייל למשרד** עם מה נכנס. בקליקטאק הוא אומר במפורש לאיזה סניף ומזכיר שאפשר
   לבטל, כי זה הדבר היחיד שהקובץ לא יכול לאמת בעצמו.

## דוגמה שעובדת מקצה לקצה

```bash
#!/usr/bin/env bash
set -euo pipefail

API="https://gan-halomot.onrender.com"
KEY="<IMPORT_BOT_SECRET>"          # מ-Render. לא בקוד ולא ב-git.

sign() {
  TS=$(date +%s)
  SIG=$(printf '%s.' "$TS" | openssl dgst -sha256 -hmac "$KEY" -hex | sed 's/.* //')
}

# ── סיבוס: החודש נגזר לבד מהתאריך ─────────────────────────────────────
sign
curl -sS -X POST "$API/api/import-bot/cibus" \
  -H "X-Import-Key: $KEY" -H "X-Import-Ts: $TS" -H "X-Import-Sig: $SIG" \
  -F "file=@/tmp/cibus.xlsx"

# ── קליקטאק: קובץ לכל סניף, בדיקה ואז העלאה ──────────────────────────
declare -A BRANCH=(
  [moshe_dayan]=69dde62467ff14714973a158
  [tel_aviv]=69dde62467ff14714973a15c
  [herzliya]=69df6a19dcde21f40a7a020b
)

for name in "${!BRANCH[@]}"; do
  FILE="/tmp/clicktac-$name.xlsx"
  ID="${BRANCH[$name]}"

  sign
  curl -sS -X POST "$API/api/import-bot/clicktac/validate" \
    -H "X-Import-Key: $KEY" -H "X-Import-Ts: $TS" -H "X-Import-Sig: $SIG" \
    -F "file=@$FILE" -F "branch_id=$ID"

  sign
  curl -sS -X POST "$API/api/import-bot/clicktac" \
    -H "X-Import-Key: $KEY" -H "X-Import-Ts: $TS" -H "X-Import-Sig: $SIG" \
    -F "file=@$FILE" -F "branch_id=$ID"
done
```
